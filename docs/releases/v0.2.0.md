# IUCE Reservas v0.2.0 — Calendario, panel administrativo y rework visual

[![SonarCloud Quality Gate](https://sonarcloud.io/api/project_badges/measure?project=ShockyDEV_IUCE-Reservas-TFG&metric=alert_status)](https://sonarcloud.io/summary/new_code?id=ShockyDEV_IUCE-Reservas-TFG)

Segunda release del Trabajo de Fin de Grado **IUCE Reservas**, sistema web de gestión de reservas de espacios académicos del Instituto Universitario de Ciencias de la Educación (IUCE) de la Universidad de Salamanca.

Esta versión hereda toda la funcionalidad de [v0.1.0](https://github.com/ShockyDEV/IUCE-Reservas-TFG/releases/tag/v0.1.0) (autenticación con magic link, catálogo de espacios, motor de reservas, aprobación administrativa y notificaciones por correo) y recoge el resultado de los **sprints 5, 6 y 7**: añade reservas recurrentes, bloqueos administrativos, panel administrativo completo, audit log y un rework visual integral con shadcn/ui.

---

## Qué hay de nuevo desde v0.1.0

### Sprint 5 — Recurrencia y bloqueos de calendario

Se introducen las reservas recurrentes con tres patrones (`WEEKLY`, `BIWEEKLY`, `MONTHLY`). El motor expande la solicitud en instancias individuales agrupadas por `recurrenceGroupId` y omite automáticamente las que colisionan con otras reservas o con bloqueos administrativos; cada solicitud está limitada a 52 ocurrencias para evitar recurrencias accidentales muy largas.

Se añade el modelo `BlockedSlot` con la API completa `GET / POST / DELETE`, pensado para que el personal administrativo bloquee franjas por mantenimiento, vacaciones o eventos institucionales. La validación de `POST /api/reservations` se refuerza para rechazar cualquier solapamiento con reservas en estado `PENDING` o `APPROVED`, así como con bloqueos activos.

En el frontend aparecen los dos componentes de calendario: `WeekCalendar` (vista semanal por espacio) y `DashboardCalendar` (mini-calendario mensual integrado en el panel del usuario).

### Sprint 6 — Panel administrativo y audit log

El dashboard `/admin` consolida en una sola pantalla las tarjetas de pendientes / aprobadas / rechazadas / total, el ranking de espacios más reservados de los últimos 30 días y las últimas entradas del audit log. La información se sirve desde el nuevo endpoint `GET /api/admin/stats`.

Llega la API completa de gestión de usuarios (`GET /api/admin/users`, `PATCH /api/admin/users/[id]`) con protección jerárquica: solo otro `SUPER_ADMIN` puede modificar el rol de un `SUPER_ADMIN`. La gestión de espacios añade alta, edición y soft delete (`isActive=false`) que conserva las reservas históricas.

Se incorpora el modelo `AuditLog` con un catálogo cerrado de ocho acciones administrativas (`RESERVATION_APPROVED`, `RESERVATION_REJECTED`, `BLOCKED_SLOT_CREATED`, `BLOCKED_SLOT_DELETED`, `USER_ROLE_CHANGED`, `SPACE_CREATED`, `SPACE_UPDATED`, `SPACE_DEACTIVATED`) y un helper `requireAdmin()` que centraliza la guarda de rol y elimina las duplicaciones que SonarCloud detectaba en los siete endpoints administrativos.

### Sprint 7 — UX y Mobile (rework visual a shadcn/ui)

El sprint más visible: migración del sistema de componentes a `shadcn/ui` (`Button`, `Card`, `Input`, `Textarea`, `Badge`), con la paleta corporativa USAL/IUCE y los tokens `brand`, `success`, `warning` y `danger`. Se incorporan `lucide-react` para los iconos y `react-hot-toast` para el sistema de notificaciones.

Aparece una navbar global con menú adaptativo por rol (los enlaces del panel administrativo solo se muestran si el usuario es `ADMIN` o `SUPER_ADMIN`) y un footer institucional con el bloque corporativo y el enlace a las normas. Toda la aplicación pasa por un rediseño visual completo: landing, sign-in con layout dividido, dashboard, catálogo, ficha de espacio, formulario de reserva y panel administrativo.

El soporte responsive llega hasta 375 px con tap targets de 44 px mínimo. La suite de tests se amplía con `@testing-library/react` y `jsdom` para cubrir los componentes UI principales.

### Pulido posterior al cierre del Sprint 7 (26 may)

Antes de publicar la release se completan tres pantallas administrativas cuya API ya existía desde sprints anteriores:

- `/admin/spaces` — CRUD completo de espacios con alta, edición y desactivación.
- `/admin/users` — listado de usuarios con cambio de rol inline respetando la jerarquía.
- `/admin/blocked-slots` — listado, creación y eliminación de bloqueos administrativos.

Junto con un fix del logo institucional en el banner azul de `/auth/signin`.

## Levantar el proyecto en local

> Requisitos: Node.js 20+, Docker y Docker Compose, Git.

```bash
git clone https://github.com/ShockyDEV/IUCE-Reservas-TFG.git
cd IUCE-Reservas-TFG
git checkout v0.2.0

npm install
cp .env.example .env

docker-compose up -d
npm run db:push
npm run db:seed

npm run dev
```

La aplicación queda disponible en [http://localhost:3000](http://localhost:3000).

Con `NEXT_PUBLIC_USE_MOCK_AUTH=true` (valor por defecto en `.env.example`), la pantalla `/auth/signin` muestra los tres botones de acceso rápido que permiten evaluar la aplicación completa sin cuenta `@usal.es` ni configurar Resend.

Otros comandos útiles:

```bash
npm run test           # Ejecuta los 65 tests unitarios
npm run build          # Compila para producción (Next.js standalone)
npm run db:studio      # Abre Prisma Studio (UI de la base de datos)
```
